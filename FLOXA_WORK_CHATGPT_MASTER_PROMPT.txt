1. PROJECT OVERVIEW & CORE PHILOSOPHY
--------------------------------------------------------------------------------
FLOXA Work is built to replace the friction, generic cover letters, and escrow
custody delays of legacy platforms (like Upwork or Fiverr) with a modern, high-
craft, discovery-first experience based on FLOXA Design principles.

Core Principles:
1. Discovery-First Bidding (The Mini-Discovery Pitch):
   Instead of writing generic proposals, freelancers submit a structured problem
   diagnosis, an execution direction slider (e.g., 80% Consumer Friendly vs.
   Formal), and a 3-milestone execution plan.
2. Direct Milestone Billing (Zero Platform Escrow Holding):
   The platform never holds user funds in custody escrow. Instead, contracts follow
   a Direct Milestone Billing structure (Advance 40% on acceptance, Mid 40% on
   deliverable handover, and Final 20% on final asset release). Milestone approvals
   record direct disbursement references (DIRECT_PAY_...) in MongoDB with permanent
   state persistence.
3. Global Real-Time Presence & Telephony:
   Users remain continuously ONLINE across all tabs and views. A persistent
   application-level WebSocket connection handles real-time online status, rich
   notification toasts, and browser-to-browser WebRTC video/audio screening calls
   with synthetic telephone ringing chimes (Web Audio API) that ring anywhere on
   the site.
4. Daylight Frosted Glass & Smoky Design System:
   Ultra-clean light frosted glass aesthetic with deep slate black typography
   (#0f172a), electric royal blue accents (#0084ff), metallic wave banners, and
   zero decorative emojis.

2. TECHNOLOGY STACK & PORTS
--------------------------------------------------------------------------------
- Frontend:
  * Framework: Next.js 16 (App Router) with React 19
  * Language: TypeScript
  * Styling: Tailwind CSS & custom glassy CSS utilities (globals.css)
  * Icons: Lucide React (clean SVG icons, zero emojis)
  * Audio: Zero-dependency Web Audio API dual-frequency synthesizer
    - Telephone Ringtone: 440Hz/480Hz (outgoing) & 523Hz/659Hz (incoming)
    - Notification Ping: 880Hz -> 1320Hz ascending bell chime
  * WebSockets: Native browser WebSocket connecting to backend ws://
  * Video/Audio Calling: Direct WebRTC screening room with camera/mic controls
  * Local Server Port: http://localhost:3001

- Backend:
  * Runtime: Node.js (v20+) with Express
  * Language: TypeScript (compiled via tsc to dist/)
  * Database: MongoDB with Mongoose ODM (mongodb://127.0.0.1:27017/floxa_work_db)
  * Real-Time Server: Native `ws` WebSocketServer mounted on the HTTP server at `/ws`
  * Authentication: JWT (jsonwebtoken, 7-day expiration) & bcryptjs password hashing
  * Security: Input sanitization, ObjectId validation, role middleware
  * Local Server Port: http://localhost:5001
  * WebSocket Endpoint: ws://localhost:5001/ws

4. DATABASE MODELS & SCHEMAS
--------------------------------------------------------------------------------
1. User (Collection: 'users')
   - email: String (unique, lowercase, trim)
   - passwordHash: String (bcrypt)
   - name: String (e.g., 'Aravind V.', 'Sanjay Mehta')
   - handle: String (unique, e.g., 'aravind_design')
   - role: 'freelancer' | 'client' | 'dual' | 'admin'
   - avatarUrl: String (Unsplash or custom image URL)
   - isVerified: Boolean (default: false)
   - timestamps: true

2. TalentProfile (Collection: 'talent_profiles')
   - userId: ObjectId ref 'User' (unique index)
   - headline: String (e.g., 'Brand Identity & Visual Design Systems Lead')
   - bio: String (Consultant methodology and craft)
   - skills: [String] (e.g., ['Brand Identity', 'Design Systems', 'Figma', 'UI/UX Tokens'])
   - hourlyRate: Number (default: 85)
   - minimumProjectBudget: Number (default: 500)
   - availabilityStatus: 'available' | 'busy' | 'not_looking'
   - completedContractsCount: Number (auto-incremented on contract completion)
   - escrowVolumeEarned: Number (sum of released direct payments)
   - ratingAverage: Number (default: 5.0)

3. Brief (Collection: 'briefs')
   - clientId: ObjectId ref 'User'
   - title: String (e.g., 'Visual Identity & Design System for HealthTech AI')
   - category: 'branding' | 'uiux' | 'webdev' | 'marketing'
   - problemStatement: String (Detailed technical / business problem)
   - targetAudience: String
   - deliverablesRequired: [String]
   - sliders: [{ key: String, leftLabel: String, rightLabel: String, value: Number }]
   - budgetMin: Number, budgetMax: Number
   - currency: String (default: 'USD')
   - deadlineWeeks: Number
   - status: 'open' | 'in_review' | 'assigned' | 'completed' | 'cancelled'
   - proposalsCount: Number (counter)
   - magicLinkToken: String (48-char random hex)

4. Proposal (Collection: 'proposals')
   - briefId: ObjectId ref 'Brief'
   - freelancerId: ObjectId ref 'User'
   - diagnosticAnswers: [{ question: String, answer: String }]
   - strategicSliders: [{ key: String, value: Number }]
   - proposedMilestones: [{
       title: String,
       description: String,
       amount: Number,
       deliveryDays: Number
     }] (Auto-normalized: 40% Advance, 40% Mid, 20% Final)
   - totalPrice: Number
   - estimatedDays: Number
   - status: 'pending' | 'accepted' | 'declined' | 'withdrawn'

5. Contract (Collection: 'contracts')
   - briefId: ObjectId ref 'Brief'
   - proposalId: ObjectId ref 'Proposal'
   - clientId: ObjectId ref 'User'
   - freelancerId: ObjectId ref 'User'
   - totalBudget: Number
   - currency: String (default: 'USD')
   - status: 'active' | 'completed' | 'disputed' | 'cancelled'
   - msaAgreementSignedAt: Date
   - clientSignature: String
   - floxaDesignWorkspaceLinked: Boolean

6. Milestone (Collection: 'milestones')
   - contractId: ObjectId ref 'Contract'
   - milestoneNumber: Number (1, 2, 3)
   - title: String
   - description: String
   - amount: Number
   - escrowState: 'awaiting_deposit' | 'held_in_escrow' | 'in_review' | 'released'
   - paymentGatewayRef: String (e.g., 'DIRECT_PAY_ADVANCE_...' or 'DIRECT_PAY_MILESTONE_...')
   - submissions: [{
       fileUrls: [String],
       notes: String,
       submittedAt: Date
     }]
   - reviewDeadline: Date (7-day window)
   - approvedAt: Date, releasedAt: Date

7. SocialPost (Collection: 'social_posts')
   - authorId: ObjectId ref 'User'
   - caption: String
   - mediaUrls: [String]
   - mediaType: 'image' | 'video' | 'case_study'
   - tags: [String]
   - projectCategory: String
   - likesCount: Number, commentsCount: Number
   - likedBy: [ObjectId ref 'User']

8. ChatMessage (Collection: 'chat_messages')
   - senderId: ObjectId ref 'User'
   - recipientId: ObjectId ref 'User'

WORKFLOW 1: AUTHENTICATION & LOGIN

  * Freelancer: email: freelancer@floxa.work | password: Password123!

  * Backend calls POST /api/auth/login.

  * Redirects client to `client_dashboard` and freelancer to `briefs`.

WORKFLOW 2: CLIENT POSTS A GUIDED BRIEF
- Location: Topbar "Post Brief" button or Client Dashboard.
- Modal: PostBriefModal.tsx
- Inputs Required:
  1. Brief Title (e.g., "Visual Identity for AI Clinical Platform")
  2. Category: branding | uiux | webdev | marketing
  3. Problem Statement (Detailed clinical/product friction)
  4. Target Audience (e.g., "Clinical researchers and everyday patients")
  5. Required Deliverables (e.g., "Logo Suite, Figma Tokens, Style Guide")
  6. Strategic Slider: Speed/MVP (0%) vs. Craft/Pixel-Perfect (100%)
  7. Budget Min ($1,800) & Budget Max ($2,800)
  8. Estimated Timeline (Weeks)
- Backend Action:
  * POST /api/briefs with Authorization Bearer header.
  * Status set to 'open', magicLinkToken generated.
  * Dispatches toast: "Brief published to marketplace!".

WORKFLOW 3: FREELANCER SUBMITS A MINI-DISCOVERY PITCH
- Location: Explore Briefs (BriefsView.tsx) -> Click "Submit Pitch" on an open brief.
- Modal: MiniDiscoveryModal.tsx
- Inputs Required:
  1. Problem Diagnosis: Diagnostic text explaining the solution (e.g., "Patient
     intake requires strict compliance; proposing 3-archetype consumer tokens.")
  2. Execution Direction Slider: e.g., 80% Consumer Friendly
  3. Total Bid Price ($2,400)
  4. Milestones: Auto-divided into 3 direct milestone splits:
     - Milestone 1: 40% ($960) — Discovery & Concept Exploration (7 Days)
     - Milestone 2: 40% ($960) — Production & Asset Engineering (7 Days)
     - Milestone 3: 20% ($480) — Final Delivery & Handover (7 Days)
- Backend Action:
  * POST /api/proposals with briefId, diagnosticAnswers, proposedMilestones, totalPrice, estimatedDays.
  * Proposal saved with status 'pending'.
  * WebSocket emits `system_notification` to client.
  * Freelancer redirected to "My Pitches" tab (`mini-discovery`).

WORKFLOW 4: CLIENT ACCEPTS PROPOSAL & DISBURSES ADVANCE DIRECTLY
- Location: Client Dashboard -> Tab: "Review Proposals".
- The proposal card displays:
  * Freelancer profile picture, @handle, and verified badge.
  * Full problem diagnosis text.
  * Execution direction slider visual preview.
  * Bid summary: $2,400 Total, 3 Milestones, 21 Days.
- Actions:
  * Button 1: "Video Interview" (initiates live WebRTC call).
  * Button 2: "Accept Proposal & Pay Advance ($960)".
- Backend Action on Click:
  * Calls POST /api/contracts with { proposalId, clientSignature }.
  * Creates Contract in MongoDB (status: 'active').
  * Inserts 3 Milestone documents:
    - Milestone 1: escrowState: 'released', paymentGatewayRef: 'DIRECT_PAY_ADVANCE_<timestamp>', approvedAt, releasedAt.
    - Milestone 2: escrowState: 'awaiting_deposit'.
    - Milestone 3: escrowState: 'awaiting_deposit'.
  * Proposal marked 'accepted', Brief marked 'assigned'.
  * WebSocket notifies freelancer: "Proposal Accepted & Advance Paid ($960 directly)!".
  * Client button changes to permanent badge: "Proposal Accepted & Advance Paid".

WORKFLOW 5: ACTIVE CONTRACT WORKSPACE & MILESTONE LIFECYCLE
- Location: "Milestones" / "Active Contract" (WorkspaceView.tsx).
- Unified view for both Client and Freelancer.
- Step Navigation:
  * Milestone 1 ($960): Shows "Paid Directly", status: 'released'. Payment reference: DIRECT_PAY_ADVANCE_...
  * Milestone 2 ($960):
    - When Awaiting: Freelancer sees "Submit Milestone Deliverable" button.
      Modal accepts deliverable bundle name and handover notes.
      Submitting calls POST /api/milestones/:id/deliverable.
      Moves milestone to `in_review` (7-Day Inspection Window).
    - When In Review: Client sees "Approve Deliverable & Pay Milestone ($960)" button.
      Client clicks button -> calls POST /api/milestones/:id/approve.
      Backend sets `escrowState: 'released'`, sets paymentGatewayRef: DIRECT_PAY_MILESTONE_<timestamp>.
      Updates MongoDB. State reloaded.
      Permanently shows "Approved & Paid Directly" (green banner).
      **State is permanently saved in MongoDB and never reverts on refresh.**
  * Milestone 3 ($480): Final delivery handover follows identical lifecycle.
    When Milestone 3 is approved, contract status moves to 'completed', and
    freelancer's `completedContractsCount` increments in MongoDB.

WORKFLOW 6: GLOBAL REAL-TIME WEBSOCKETS, TOASTS & WEBRTC CALLING
- Root Level Socket (page.tsx):
  * Instantiated as soon as user logs in. Never unmounts on tab switches.
  * Presence heartbeat every 20 seconds.
  * Tracks `onlineUsers` roster. Users stay **Online** on all tabs.
- Telephone Ringing Signaling:
  * User A clicks "Video Call" in ChatView.
  * Socket emits: `{ type: 'call_user', callerId, callerName, callerAvatar, callType: 'video' }`.
  * User B is on Workspace, Briefs, or Pitches tab:
    - Ringtone synthesizer starts dual-frequency incoming chime (523Hz/659Hz).
    - Frosted glass Incoming Call Modal renders globally over the page.
    - Displays caller avatar with glowing ping halo, caller name, and Accept / Decline buttons.
    - User B clicks "Accept":
      * Ringtone stops.
      * Socket sends `call_accepted`.
      * App immediately transitions to `chat` tab.
      * Live WebRTC video screening room opens with local/remote streams, mute mic, video toggle, timer, and End Call button.
    - User B clicks "Decline":
      * Ringtone stops.
      * Socket sends `call_declined`.
      * Caller receives notification "Call Declined".
- Rich Floating Notification Toasts:
  * When a message or event arrives while viewing another tab:
    - Synthesizer plays pleasant 2-tone bell chime.
    - Floating frosted glass toast appears at top-5 right-5:
      * Sender circular avatar with blue indicator dot.
      * Header: Sender Name + "Just now" + X close button.
      * Body: Message text preview.
      * Action Button: "Reply / View Chat" (takes directly to chat tab).
      * Auto-dismisses in 6 seconds.
  * Bell Icon in topbar increments unread badge.
  * Clicking Bell opens notification dropdown listing all activity.
